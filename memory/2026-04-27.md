### wget 重新抓取的教训

**错误参数（第 1 次）**：
```bash
wget --mirror --convert-links --adjust-extension -r -l 3 -nH --cut-dirs=2
```
- `-nH --cut-dirs=2` 砍掉了 `hiyamax-home/` 和 `assets/` 两层
- 结果：资源散落到了 `css/`、`images/`、`js/` 而非 `assets/css/` 等
- `--convert-links` 制造绝对 URL 污染
- `--adjust-extension` 破坏文件扩展名

**正确参数（第 2 次）**：
```bash
wget --mirror --page-requisites -r -l 3 https://hiyascott.github.io/hiyamax-home/
```
- 不用 `-nH --cut-dirs`
- 不用 `--convert-links`
- 不用 `--adjust-extension`
- 结果：65 个文件，1.3M，目录结构正确
- 但**只抓到一级页面**（games/index.html, books/index.html, artworks/index.html, hiyamax/index.html）
- **没有抓到三级子页面**（如 artworks/abstract-birds/index.html）

**原因分析**：
- GitHub Pages 上的链接可能是 JS 动态生成的
- wget 无法执行 JS，所以看不到子页面链接
- `r -l 3` 理论上应该递归，但没有链接可跟随

### Nginx + PHP-FPM 踩坑

**问题**：`hiyamax.cn` 502 Bad Gateway

**排查过程**：
1. 宝塔原始配置用 `include /www/server/nginx/conf/enable-php-74.conf;` 引用 PHP 配置
2. `enable-php-74.conf` 文件**不存在**
3. PHP-FPM 进程在运行，但 socket 文件 `/tmp/php-cgi-74.sock` 也**不存在**
4. 改为 `unix:/tmp/php-cgi-74.sock` 后 `hiyamax.online` 200 成功，`hiyamax.cn` 却返回 Nginx 默认页

**根本原因待查**：宝塔可能自动恢复了配置，或 Nginx 配置未完全生效。

### 严重教训：sub-agent 跑错环境

用 `sessions_spawn` 创建 sub-agent 做服务器诊断，结果它在**本地 workspace** 执行，而不是用户的阿里云服务器。

**原因**：`exec` 命令在 sub-agent 中执行时，默认在 agent 所在的主机运行（即 OpenClaw 服务器），而非用户通过 SSH 连接的目标服务器。

**正确做法**：
- 服务器操作必须**让用户复制粘贴命令执行**
- 不能用 sub-agent 做远程服务器诊断（除非有 agent 部署在目标服务器上）
- 任何涉及远程主机的操作，先明确确认执行环境
