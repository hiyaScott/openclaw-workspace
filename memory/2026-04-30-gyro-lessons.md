# 2026-04-30 经验教训 - hiyamax.com 陀螺仪调试

## 问题
hiyamax.com 主页头像陀螺仪动画在鸿蒙手机上无响应。

## 踩过的坑

### 坑1：过度假设，不先验证
- 假设鸿蒙需要特殊处理 → 加了 `requestPermission` 判断
- 实际上 gyro-test.html 没有任何特殊处理就能工作
- **教训**：先移植能工作的代码，再差异化调试，不要预设平台差异

### 坑2：把简单问题复杂化
- gyro-test.html 的逻辑：直接 `window.addEventListener('deviceorientation', handler)`
- 我加的：iOS 权限请求、用户交互监听、Promise 链、错误处理...
- 结果：把原本能工作的代码改坏了
- **教训**：测试页能工作 → 正式页应该完全一致，不要"优化"

### 坑3：改动确认能工作的代码
- iOS 的权限请求逻辑在 v1.5.1 是能工作的
- 我为了"兼容鸿蒙"改了结构，结果 iOS 也坏了
- **教训**：不要改动确认能工作的代码，新增代码应该隔离

### 坑4：混淆了不同仓库
- hiyamax.com 实际 served 的是 `hiyamax-home` 仓库
- 我先改了 `scott-portfolio/research/max-home/`（测试页面）
- 浪费了大量时间，改错了地方
- **教训**：部署前确认目标仓库和实际 served 的域名对应关系

### 坑5：CDN 缓存导致验证混乱
- GitHub Pages CDN 缓存 2-5 分钟
- 我反复修改、验证、认为没生效，又继续改
- 实际上可能是缓存没刷新，不是代码问题
- **教训**：修改后等 5 分钟再验证，避免反复修改

## 正确做法（事后总结）

1. **先确认问题存在**：用原始代码在鸿蒙上测试，确认确实不工作
2. **移植测试页**：把 gyro-test.html 的代码原样复制到正式页
3. **隔离验证**：只改一处，等 CDN 刷新后验证
4. **逐步差异化**：如果测试页能工作而正式页不能，再排查差异（CSS 遮挡？DOM 结构？事件冲突？）
