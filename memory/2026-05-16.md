## 合并单 APK 技术细节补充

**文件结构：**
- base.apk (31MB) → 包含核心代码、资源、AndroidManifest
- split_config.arm64_v8a.apk (11.6MB) → `lib/arm64-v8a/` 下 10 个 .so 库（hermes、reactnative、fbjni 等）
- split_config.xxhdpi.apk (84KB) → `res/drawable-xxhdpi-v4/` 高清图片资源
- split_config.zh.apk (41KB) → 中文语言资源

**合并步骤：**
1. 解压 base.apk
2. 将 arm64 split 的 lib/ 目录复制进 base
3. 将 xxhdpi split 的 res/drawable-xxhdpi-v4/ 复制进 base
4. 用 zip 重新打包
5. zipalign -p 4 对齐
6. apksigner 用测试证书签名（v2 + v3 scheme）

**关键教训：**
- 不要尝试用 bundletool 的 `build-apks` 反向操作，bundletool 不支持从已安装的 split APK 反编译
- 手动 zip 合并是最可靠的方法，只要对齐和签名步骤正确
- apksigner 需要真实的 keystore 文件，不能传 /dev/null
- zipalign 后的文件必须再用 apksigner 签名，否则安装器会报 "not aligned"

## 合并单 APK 安装失败问题 (2026-05-16 14:08)

用户反馈合并后的单 APK 安装出错。

**可能原因：**
1. 中文 split (split_config.zh.apk) 的 resources.arsc 没有合并进 base → 缺少中文字符串资源

**尝试修复：**
- 下载 apktool 进行资源反编译/重新打包 → 从 bitbucket 和 GitHub 下载的 jar 文件均损坏（可能网络限制导致下载不完整）
- bundletool 也不支持从 split APK 反向合并

**最终建议：**
直接用 SAI 安装原始的 `.apks` 文件是最可靠的方案。SAI 专门设计用于安装 split APK，不需要手动合并。合并单 APK 对 React Native 应用来说容易出问题。

## APKPure/SAI 下载困难 (2026-05-16 16:53)

用户需要 APKPure 安装器来安装 .apks 文件，但服务器端无法下载 APKPure APK：
- APKPure CDN (d.apkpure.net) 被 Cloudflare 拦截
- GitHub releases 下载超时（限速）
- ghproxy 镜像也超时
- 所有 APK 镜像站均不可达

**最终给用户的方案：**
1. 酷安应用市场搜「SAI」或「APKPure」直接下（最推荐）
2. 华为/小米/OPPO 应用商店搜
3. https://a2zapk.io/ 输入包名提取 APK（国内可访问）
4. 用 MT 管理器替代 SAI（国产，支持 split APK，兼容性更好）
