# 2026-04-29 - hiyamax.com 陀螺仪修复调试

## 问题
hiyamax.com 主页头像模块在手机上陀螺仪倾斜无响应。

## 根因分析

### iOS Safari
- v1.6.0 引入 `touchstart` 权限请求，消耗了 `{ once: true }` 机会，导致后续 `click` 不再触发权限弹窗
- v1.6.1/v1.6.2 用块级函数声明 `function requestIOSPermission() {}` 在 Safari 严格模式下解析失败
- **v1.6.3 修复**：改回函数表达式 `document.body.addEventListener('click', function requestIOSPermission() {...}, { once: true })` + `removeEventListener` 双重保险
- iOS 隐私模式已验证正常，点击屏幕后弹权限菜单，陀螺仪响应正常

### Android / HarmonyOS（鸿蒙）
- `deviceorientation` 事件完全为 0 — Chrome/HarmonyOS 浏览器需要 `Permissions-Policy` 声明才允许传感器
- v1.5.1 原始代码没有 fallback，`devicemotion` 的 `rotationRate` 在很多 Android 手机上为 null
- `accelerationIncludingGravity` 数据用 `atan2` 转换后值只有 1-2 度，几乎为零（坐标系差异）
- **v1.5.2 修复**：保留 v1.5.1 原始 `deviceorientation` 逻辑，新增 `devicemotion` fallback 直接用原始 `acc.x / 5` 和 `acc.y / 5` 驱动 avatar，跳过角度转换

## 参数映射（确认一致）

| 方向 | 传感器轴 | 分母 | 说明 |
|------|---------|------|------|
| 竖屏 portrait | `gamma` | **12** | 手机倾斜约 12° 达到满偏移 |
| 横屏 landscape | `beta` | **8** | 手机倾斜约 8° 达到满偏移 |

v1.5.1 → v1.6.x 这个参数从未改动过。

## 调试面板

左下角黑色调试面板显示：
- gamma / beta / alpha：原始传感器值
- percent：计算出的 avatar 偏移值
- orientation：portrait / landscape
- events：事件累计次数
- hasGyro：是否检测到有效陀螺仪数据
- UA：浏览器标识（用于判断设备类型）

## 鸿蒙 HarmonyOS 特殊处理

- 系统设置：**设置 → 隐私 → 权限管理 → 应用获取设备方向** 必须为「开启」
- 鸿蒙浏览器基于 Chromium，可能需要 `Permissions-Policy` meta 标签
- `DeviceOrientationEvent` 可能不被支持，但 `DeviceMotionEvent` 的 `accelerationIncludingGravity` 应该可用

## 教训
1. **不要改动确认能工作的代码结构** — iOS 的函数表达式 vs 函数声明差异在 Safari 有实际影响
2. **Android/HarmonyOS 需要多层 fallback** — `deviceorientation` → `devicemotion` (acceleration) → 自动摆动
3. **调试面板是必需品** — 没有数值反馈时无法定位问题层级
