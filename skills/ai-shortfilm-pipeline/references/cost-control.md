# 伪代码示例
MAX_PROJECT_BUDGET = 100  # 项目总预算

## 三、成本控制策略

### 3.1 免费工具先行

**概念验证阶段**（免费）：
- 豆包：角色设计、首帧生成
- 海螺免费额度：视频测试

**确认方向后**（付费）：
- 即梦v2.0：高质量场景
- 可灵：最终视频生成

### 3.2 缩略图预览法

**流程**：
1. 低质量/小尺寸生成预览
2. 用户确认效果
3. 高质量生成最终版

**节省估算**：
- 预览成本：¥0.1/张
- 最终成本：¥0.5/张
- 节省比例：80%（如果预览不通过）

### 3.3 批量生成控制

**正确做法**：
```python
# 先测试1个
result = generate_video(test_prompt, test_image)
if user_approve(result):
    # 用户确认后再批量
    for i in range(3):
        generate_video(prompt, image)
        time.sleep(30)  # 间隔30秒
```

**错误做法**（会导致资金浪费）：
```python
# ❌ 不要这样做！
for i in range(20):
    generate_video(prompt, image)  # 一口气生成20个
```

### 3.4 复用已有素材

**同项目内复用**：
- 角色设计复用于多个场景
- 场景元素复用于多个镜头

**跨项目复用**：
- 通用场景（天空、地面、植物）
- 标准元素（警示灯、机械零件）

## 四、API调用安全规范

### 4.1 调用频率限制

**最小间隔**：
- 视频生成：30秒/次
- 图像生成：5秒/次
- 查询状态：10秒/次

**最大重试**：
- 失败重试：最多3次
- 超时重试：最多5次

### 4.2 错误处理规范

```python
def safe_api_call(prompt, image, max_retries=3):
    """安全的API调用封装"""
    for i in range(max_retries):
        try:
            result = api.generate(prompt, image)
            return result
        except Exception as e:
            if i == max_retries - 1:
                raise  # 最后一次失败，抛出异常
            time.sleep(30)  # 等待后重试
```

### 4.3 查询与提交分离

**致命错误示例**：
```python
# ❌ 错误：查询时创建新任务
while not completed:
    response = requests.post(API_SUBMIT_URL, ...)  # 每次都在提交！
    time.sleep(10)
```

**正确做法**：
```python
# ✅ 正确：先提交，再查询
# 1. 提交任务
task_id = requests.post(API_SUBMIT_URL, json={...}).json()["task_id"]

# 2. 查询状态
while not completed:
    response = requests.post(API_QUERY_URL, json={"task_id": task_id})
    if response.json()["status"] == "completed":
        break
    time.sleep(30)
```

### 5.2 预算预警机制

**预警阈值**：
- 50%预算：提醒用户
- 80%预算：停止自动操作，需人工确认
- 100%预算：完全停止

**预警消息模板**：
```
⚠️ 预算预警

项目：第147天
已使用：¥80 / ¥100 (80%)

建议：
1. 完成当前任务后暂停
2. 评估剩余工作量
3. 如需继续，请确认增加预算
```

### 5.3 成本复盘

**每次项目结束后**：
1. 统计实际成本 vs 预算
2. 分析超支原因
3. 记录节省技巧
4. 更新预算模型

## 六、事故案例与教训

### 6.1 API滥用事故

**时间**：2026-03-29 凌晨
**损失**：¥43.2（27次无效调用 × ¥1.6）

**事故经过**：
1. 将查询代码误写为提交代码
2. 每10-12秒"查询"一次（实际在创建新任务）
3. 持续47分钟，共提交27次
4. 全部浪费，没有正确获取视频

**根本原因**：
1. 脚本逻辑错误
2. 缺乏调用频率限制
3. 没有设置最大重试次数
4. 无视用户"先等我确认"的指令

**改进措施**：
1. 代码审查制度（关键逻辑必须验证）
2. 调用频率限制（≥30秒间隔）
3. 预算上限硬限制
4. 高风险操作必须获得用户明确授权

### 6.2 缓存问题导致的重复生成

**问题**：
- 图片显示问号
- 多次尝试重新生成
- 浪费API调用

**解决方案**：
1. 建立QA验证脚本
2. 用户验收前必须自检
3. 服务端验证 ≠ 真实浏览器验证
