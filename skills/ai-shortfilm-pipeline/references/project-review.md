## 一、复盘时机

### 1.1 触发条件

- 项目正式发布后24小时内
- 遇到重大问题时立即复盘
- 每月定期回顾（如果有多项目并行）

### 1.2 复盘参与者

- **必须**：Scott（导演/决策者）、Jetton（执行者/AI助手）
- **可选**：外部反馈者（如果已发布）

## 五、Skill更新流程

### 5.1 更新触发条件

根据复盘结果，确定是否需要更新Skill：

| 情况 | 处理方式 |
|------|----------|
| 发现流程漏洞 | 更新SKILL.md工作流程 |
| 新工具/新技巧 | 更新ai-tools-guide.md |
| 提示词效果验证 | 更新prompt-templates.md |
| 成本控制新发现 | 更新cost-control.md |
| 复盘模板不足 | 更新本文件 |

### 5.2 更新流程

1. **识别改进点**（复盘阶段）
2. **起草更新**（修改对应文件）
3. **验证更新**（测试新流程/模板）
4. **打包Skill**（生成新的.skill文件）
5. **记录变更**（在Skill中记录版本更新日志）
6. **下次使用**（新项目使用更新后的Skill）

### 5.3 版本更新日志格式

在 `SKILL.md` 末尾添加：
```markdown
## 迭代记录

### v1.1 (2026-04-XX)
- 新增：XXX工具的最佳实践
- 优化：XXX流程的效率
- 修复：XXX问题

### v1.0 (2026-03-31)
- 基础5步工作流程
- 人机协作规范
- QA检查清单
```

## 七、复盘最佳实践

### 7.1 复盘原则

1. **对事不对人** — 讨论流程问题，不指责个人
2. **数据说话** — 用时间和成本数据支撑结论
3. **聚焦改进** — 重点在未来如何做得更好
4. **及时记录** — 复盘结果当天记录到Skill

### 7.2 避免的坑

- ❌ 走过场 — 不复盘或敷衍了事
- ❌ 只报喜不报忧 — 回避问题和教训
- ❌ 只记录不改进 — 复盘后不更新Skill
- ❌ 拖延复盘 — 项目结束后太久才复盘

### 7.3 复盘的价值

- **个人成长** — 从每个项目中学习
- **流程优化** — 持续改进工作流
- **知识沉淀** — 经验写入Skill，避免重复踩坑
- **协作提升** — 优化人机协作模式
