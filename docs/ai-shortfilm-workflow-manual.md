## 一、协作机制总览

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  飞书讨论    │────▶│  AI平台执行  │────▶│  Web呈现    │
```

## 二、详细流程说明

### Step 1: 飞书讨论 → 需求确认

**触发条件**：用户在飞书发送项目启动指令

**用户操作**：
- 说明项目类型（AI短片/其他）
- 提供核心创意/参考资料
- 明确交付物要求（视频/图片/文档等）

**AI助手响应**：
- 确认理解需求
- 提出关键决策点供用户选择
- 输出：更新 pipeline.html 页面，记录讨论要点

**沟通模板**：
```
【项目启动】
项目名：________
类型：AI短片/其他____
核心创意：________
参考作品：________
预期交付：________
```

---

### Step 2: 剧本创作 → Pipeline更新

**执行方式**：飞书对话协作

**流程**：
1. **概念讨论**（飞书）
   - 确定故事核心、角色、情感基调
   - 确定时长、结构、风格

2. **AI助手整理**（自动）
   - 将讨论结果写入 `pipeline/data/{project}.json`
   - 更新 pipeline.html 展示页面

3. **用户确认**（飞书）
   - 查看 pipeline.html 上的剧本内容
   - 确认或提出修改意见

**阶段性成果样式**（Pipeline页面展示）：
```json
{
  "concept": "故事一句话描述",
  "story": {
    "core": "详细故事梗概",
    "characters": [{"name": "角色名", "type": "主角", "desc": "描述"}],
    "structure": [{"phase": "幕", "time": "时间", "content": "内容"}]
  },
  "keyMoments": ["记忆点1", "金句", "高潮"]
}
```

---

### Step 3: 视觉资产 → 即梦AI/其他平台

**执行方式**：AI平台调用（消耗Token/API额度）

**流程**：
1. **用户确认**（飞书）
   - 剧本确认后，用户明确指令："开始角色设计"

2. **AI助手执行**（即梦AI）
   - 调用即梦AI生成角色参考图
   - 如用户有手绘，使用图生图转为3D写实

3. **成果呈现**（Web）
   - 图片保存到 `assets/{project}/`
   - 更新 pipeline.html 显示参考图
   - 记录生成参数和Prompt

4. **用户确认**（飞书）
   - 确认角色形象
   - 确认进入下一阶段

**阶段性成果样式**：
- 角色参考图（PNG/JPG）
- 图片展示在 Pipeline 页面
- 包含：手绘原稿 → AI生成稿 对比

---

### Step 4: 视频生成 → 海螺/可灵API

**执行方式**：DMXAPI调用（消耗API额度）

**⚠️ 重要资金保护机制**：
- 调用前检查账户余额
- 设置最大调用次数上限（单次任务最多3次重试）
- 用户明确说"开始"后才执行
- **用户说"停"必须立即停止**

**流程**：
1. **用户明确指令**（飞书）
   - "使用[工具]生成视频"
   - 明确参数（时长、分辨率、参考图）

2. **AI助手执行**（谨慎）
   - 检查API额度
   - 提交任务并正确查询状态（区分提交/查询端点）
   - 等待任务完成，获取视频链接
   - 下载视频到本地

3. **成果呈现**（Web）
   - 视频保存到 `assets/{project}/`
   - Pipeline页面显示视频预览
   - 记录视频参数和生成成本

4. **用户确认**（飞书）
   - 确认视频质量
   - 确认或要求重新生成

**阶段性成果样式**：
- 视频片段（MP4，6-10秒/镜）
- Pipeline页面内嵌视频播放器
- 显示成本信息：调用次数 × 单价

---

### Step 5: 后期剪辑 → FFmpeg本地处理

**执行方式**：本地FFmpeg（无额外API成本）

**流程**：
1. **用户指令**（飞书）
   - "开始后期剪辑"
   - 说明字幕内容、是否需要BGM

2. **AI助手执行**（本地）
   - 合并视频片段
   - 添加硬字幕（使用Noto Serif CJK等中文字体）
   - 生成/添加BGM
   - 输出最终成片

3. **成果呈现**（Web）
   - 成片视频保存
   - Pipeline页面更新为"后期完成"

4. **用户确认**（飞书）
   - 确认成片质量
   - 确认字幕、音频无误

**阶段性成果样式**：
- 成片视频（MP4，带字幕和BGM）
- 视频信息：时长、分辨率、编码格式

---

### Step 6: 发布 → GitHub Pages部署

**执行方式**：GitHub推送

**流程**：
1. **用户指令**（飞书）
   - "部署视频"
   - 确认发布地址

2. **AI助手执行**
   - 创建专题HTML页面
   - 复制视频到部署目录
   - git commit & push
   - 更新合集索引页面

3. **成果呈现**（Web）
   - 专题页面上线（带视频播放器）
   - 合集页面添加入口
   - 提供访问链接

4. **用户验收**（飞书）
   - 确认页面可正常访问
   - 确认视频可播放

**阶段性成果样式**：
- 专题页面URL
- 合集页面URL
- Git commit记录

## 三、沟通机制规范

### 指令类型与响应标准

| 指令类型 | 示例 | AI助手响应 |
|---------|------|-----------|
| **启动指令** | "开始做AI短片" | 确认需求 → 开始Step 1讨论 |
| **确认指令** | "确认这个方案" | 记录决策 → 推进到下一步 |
| **执行指令** | "生成角色图" | 检查前提条件 → 执行 → 汇报结果 |
| **暂停指令** | "先停一下" | **立即停止** → 等待进一步指示 |
| **修改指令** | "重新生成第3个" | 执行修改 → 更新Pipeline |
| **部署指令** | "部署这个视频" | 执行发布流程 → 提供URL |

### 必须遵守的规则

1. **用户说"停"必须立即停止**
   - 无论当前进行到哪一步
   - 不要擅自继续

2. **遇到困难先问，不自己乱试**
   - API调用失败时询问用户
   - 不要反复重试导致资金浪费

3. **资金保护机制**
   - API调用前检查余额
   - 单次任务最多3次重试
   - 高频调用必须加间隔（至少30秒）

4. **阶段性确认**
   - 每完成一个Step必须用户确认
   - 不要擅自进入下一阶段

## 六、故障处理流程

### API调用失控（如第147天事故）

1. **立即停止脚本**
2. **记录事故**：调用次数、损失金额、时间范围
3. **通知用户**：汇报事故详情
4. **修复脚本**：区分提交/查询端点，加频率限制
5. **手动补救**：用户从后台获取视频链接，逐个下载
6. **更新MEMORY.md**：记录教训和防范措施

### 字幕乱码

1. **问题定位**：检查字体是否支持中文
2. **解决方案**：改用Noto Serif CJK等CJK字体
3. **重新压制**：FFmpeg重新生成视频
4. **验证**：确认中文正常显示

## 八、总结

这套流程的核心是：**飞书对话驱动 → Pipeline页面记录 → Web成果展示**

每个Step都有明确的：
- **触发条件**（用户指令）
- **执行动作**（AI助手操作）
- **成果样式**（Web展示内容）
- **确认机制**（用户验收）

通过Pipeline页面，用户可以随时查看项目进度、历史决策、成本记录，实现透明化协作。
